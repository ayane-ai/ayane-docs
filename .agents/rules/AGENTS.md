适用范围：整个文档仓库。用户在当前任务中的明确要求优先于本规则。

## 文档维护规则
- **先读相关文档**：修改前阅读产品总纲、项目整体架构及本次涉及的仓库架构，确认已有目标与决策。
- **保持目标一致**：产品总纲约束整体架构，整体架构约束仓库架构；调研建议未经确认不得成为正式决策。
- **最小修改**：只处理用户指定范围。重命名同步修复链接，目录整理不改写正文，不顺手收敛章节或重新设计架构。
- **保留已有内容**：保留用户修改、图表、代码块和示例；不因主题相近而合并文档，不以较新的导出直接覆盖正式文档。
- **统一命名和目录**：客户端仓库名为 `ayane-client`；产品、架构、调研分别放入 `product/`、`architecture/`、`research/`。仅根目录使用 `README.md`，其他目录使用中文入口文档。
- **架构文档只讲框架**：描述职责、边界、依赖和演进；除用户明确要求外，不新增实现代码示例。
- **保持系统边界**：Android、Desktop、iOS 共用基于 NomiKit 的客户端仓库，Desktop 为主；后端调用云端 OpenAI-compatible API；管理后台独立；Unity 独立发布版本化产物，不依赖 Contracts，由客户端 Bridge 负责 Agent Action Protocol 到 Unity Embodiment API 的映射。
- **链接和 Notion 层级**：本地文档使用相对链接，移动后修复引用。Notion 父子关系遵循 `architecture/文档仓库架构设计.md` 中的中文入口映射；入口文档作为父页面正文，交叉链接不改变页面归属。
- **同步有明确范围**：仅在用户要求时同步 Notion；同步前比对差异，不自动覆盖远端独立修改，不因本地文件消失而删除远端页面。
- **流程图表达清楚**：区分运行时调用、数据流和发布依赖，箭头标明含义；视觉调整不能改变架构关系。未实际渲染时，只报告静态检查结果。
- **调研标明证据**：区分已确认事实、建议和待验证事项；项目能力、许可证及版本信息附官方来源和核查日期。
- **验证与交付**：检查相对链接、命名、修改范围和正文保留情况；验证结论必须来自实际检查。默认不提交、不推送、不创建远程仓库或 PR。
- **分支策略**：本仓库允许直接在 `main` 分支上进行修改、验证和提交，无需切换到其它分支，也无需创建 `agent/*` 分支；仅当用户明确要求时才新建分支。该条优先于通用的新任务分支准备规则。
- **术语以总纲附录为准**：`product/` 下的产品文档中，正文、标题和图表使用中文术语，英文只出现在 `product/产品愿景与总纲.md` 的「附录：术语规范与词表」、首次出现的括注以及代码块中；`architecture/` 下的架构文档保留英文术语（模块名、协议名、领域对象名），但概念术语的中文写法必须与词表一致；同一概念只允许一种中文写法，禁止使用词表中的禁用别名；新增术语先补进词表再使用；平台名、动作字面量、设备能力名、JSON 字段名和仓库名一律保留英文原样。

## 架构文档代码边界
给每类文档定义固定的 `codePolicy`：

| 文档类型 | 代码策略 | 允许内容 |
|---|---|---|
| `架构设计.md` | `none` | Mermaid、文本拓扑图、表格、流程说明 |
| `工程架构.md` | `none` | Mermaid、文本拓扑图、模块矩阵、依赖表、端点表 |
| `Contracts架构设计.md` | `schema-only` | 必要的 JSON/YAML Schema 片段 |
| 实现规范 / README | `code` | Kotlin、Gradle、配置和命令示例 |
适用于 `architecture/` 下的架构设计和工程架构文档：

- 文档只描述职责、边界、依赖、数据流、运行模式、部署关系和演进条件。
- 禁止新增 Kotlin、Java、Gradle、TOML、YAML、HOCON、Bash 等实现代码或配置代码。
- 禁止使用接口签名、类定义、函数实现、Repository 实现、Koin 装配代码和 Ktor `Application.module` 代码。
- Contracts架构设计允许必要的 JSON/YAML Schema 片段。
- 包结构、模块结构和依赖关系必须使用表格、列表或架构图表达，不使用代码块表达。
- 允许保留 Mermaid 图和纯文本拓扑图。
- 启动命令、端点和路径使用行内代码表达，不使用 Bash 代码块。
- 如果实现细节有必要说明，只描述其职责和约束，并引用工程实现或未来代码仓库，不在当前文档中展开代码。
- 即使任务描述、计划或前文包含代码示例，也不得自动把代码写入架构文档；代码示例只能出现在助手回复中，除非用户明确要求修改实现规范或实际工程文件。
