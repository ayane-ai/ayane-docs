# 客户端架构设计

上位架构：[项目整体架构设计](项目整体架构设计.md)

产品目标：[产品愿景与总纲](../product/产品愿景与总纲.md)

## 1. 仓库定位

`ayane-client` 是 Android、Desktop、iOS 共用的统一跨平台客户端仓库。

客户端仓库以 [Ci-Yin/NomiKit](https://github.com/Ci-Yin/NomiKit) 为基础搭建，沿用 Kotlin Multiplatform、Compose Multiplatform、模块化和单向依赖方式。KMP 是内部实现方式，不作为仓库名称的一部分。

客户端从 NomiKit 派生后独立演进。上游更新按需吸收，只回移可复用的公共层能力与通用缺陷修复，产品专属实现留在本仓库；冲突时以本仓库架构边界与决策为准。

客户端只负责用户端体验、平台能力、会话通信和身体适配，不负责服务端推理、核心记忆或 Unity 工程实现。

客户端承载三种互动模式：聊天模式、2D 形象模式和 3D 形象模式。三种模式共用同一个 Agent 与同一个 Session，模式差异只存在于客户端表现层，不进入跨仓库协议；其中 2D 形象模式属 Phase 1 内延后项。

## 2. 端与模块

```text
ayane-client/
├── app/
│   ├── android/
│   ├── desktop/
│   ├── ios/
│   └── shared/
├── business/
├── component/
│   └── unity-bridge/
│       ├── desktop/
│       ├── android/
│       └── ios/
├── core/
├── feature/
├── gradle/
└── README.md
```

Unity 工程不放入该目录。`component/unity-bridge` 只保存客户端侧适配层和产物引用配置，实际 Unity 工程位于 `ayane-embodiment`。

### app:shared

- 跨端页面、导航、资源和应用状态。
- Session、Identity、Memory 和会话展示。
- API、WebSocket 和 Action Event 消费。
- 契约生成的 Client API 模型：只读使用，不手工修改，随契约版本更新。
- 共用 Compose UI 和客户端业务编排。
- 服务端主动行为的下行播报与打断。
- 互动模式与切换状态：聊天模式、2D 形象模式与 3D 形象模式的选择与同会话内切换。
- 表现适配状态快照与迁移：模式切换时恢复情绪、是否正在说话、注视目标与口型进度。
- Agent 列表与选择（Phase 1 列表长度为 1），以及当前 Agent 上下文（多 Agent 自助创建与跨 Agent 切换属「Phase 1 内延后项」）。
- 视觉帧与关键帧模型、上行节流策略与视觉摘要的消费（采集实现在各端 source set）。
- 登录状态、Token 存储与刷新。

### Android

- Android 应用入口、生命周期和权限。
- 麦克风、音频焦点、通知和前台服务。
- 音频采集与播放、音频会话与本地打断检测。
- 屏幕与摄像头采集、降采样、变化检测与节流，以及端侧在场检测（Phase 1）；摄像头在用户授权后开启。
- Android 本地缓存和网络恢复。
- Android Unity Library 的加载和生命周期适配。

### Desktop

- Phase 1 主验证端。
- Desktop 窗口、系统托盘和全局快捷键。
- 麦克风、音频播放、调试日志和开发工具。
- 音频采集与播放、音频会话与本地打断检测。
- 屏幕与摄像头采集、降采样、变化检测与节流，以及端侧在场检测（Phase 1）；摄像头在用户授权后开启。
- Desktop Unity Runtime 的启动、连接和异常恢复。

### iOS

- iOS 应用入口、生命周期和权限。
- `AVAudioSession`、音频播放和推送。
- 音频采集与播放、音频会话与本地打断检测（AVAudioSession）。
- 屏幕与摄像头采集、降采样、变化检测与节流，以及端侧在场检测（AVFoundation，Phase 1）；摄像头在用户授权后开启。
- iOS 本地缓存和网络恢复。
- iOS Unity Framework 的加载和生命周期适配。

## 3. 共享层边界

共享层负责：

- 网络和会话状态。
- Identity、Memory、Session 和 Action Protocol 数据模型。
- Repository、UseCase、MVI 状态和事件。
- 登录态与 Token 生命周期。
- 契约版本声明与校验：声明客户端支持的契约版本范围，Session 建立时校验契约版本与音频帧、视觉帧参数。
- 语音轮次状态、通话态下的连续音频帧收发、打断控制与主动行为播报。
- 视觉帧收发、上行策略（关键帧节流与通话态连续上行）与视觉摘要消费，以及端侧在场检测的判定规则。
- 序列化、业务错误和平台能力抽象。
- 表现适配抽象、动作映射与动作能力协商。
- 当前 Agent 上下文与切换状态（Phase 1 固定一个默认 Agent）。
- Agent State 快照的只读消费（仅用于展示，不作为权威状态）。

共享层不负责：

- Agent Runtime 的服务端实现。
- 云端模型调用和 API Key。
- Unity 工程源码。
- Android、Desktop、iOS 之间的互相调用。
- 口令校验：客户端只持有并使用 Token。
- 语音识别与合成：由服务端完成，端上只采集、播放与本地打断检测。
- 视觉理解：屏幕内容理解与人脸跟踪由服务端完成，端上只采集、降采样、节流并做本地在场检测。
- 通话的跨仓库协议：通话复用音频帧与视觉帧通道，识别、合成与视觉理解仍在服务端完成。
- 渲染器能力差异的服务端判断：动作能力协商与降级由客户端承担。

## 4. 表现适配

三种互动模式共用同一个 Agent 与同一个 Session，由表现适配层统一承接动作：

```text
Agent Action Protocol
        ↓
客户端表现适配
        ├── 聊天模式：文本与语音界面
        ├── 2D 形象模式（Phase 1 内延后项）：Live2D 运行时
        └── 3D 形象模式：各平台 Unity Bridge
                              ↓
                    Unity Embodiment API
                              ↓
                    Unity Runtime Artifact
```

表现适配负责：

- 将通用动作协议映射为各虚拟形象运行时的身体 API；Unity 是 3D 形象模式的实现。
- 动作能力协商与降级：按当前模式支持的动作子集降级表达，不阻断对话链路。
- 单一活动表现：同一时刻只运行一个虚拟形象运行时；切换模式时迁移表现适配状态，不重开会话、不重放回复。
- 按平台形态加载与管理 Unity 产物：Desktop 为独立 Runtime 进程与本地通信，Android 为进程内 Android Library，iOS 为进程内 iOS Framework。
- 处理平台生命周期、资源加载、连接、异常恢复和版本兼容。
- 虚拟形象只使用平台发布并版本化的形象，不加载用户导入的形象。
- 虚拟形象运行时不可用时降级：文本对话、Identity 与 Memory 展示不依赖表现层连接。

## 5. 依赖规则

客户端依赖：

- [Contracts 架构设计](Contracts架构设计.md)
- [Agent Service 架构设计 §14 协议边界](AgentService架构设计.md) 所描述的 Client API
- `ayane-embodiment` 发布的固定版本产物

客户端禁止：

- 直接访问后端数据库。
- 直接调用云端 LLM。
- 直接依赖 Unity 工程源码。
- 使用 Git Submodule 作为长期 Unity 依赖。
- 加载用户导入的虚拟形象：虚拟形象只使用平台发布并版本化的形象。
- 让 Android、Desktop、iOS 互相依赖。

## 6. 发布和验证

- Android、Desktop、iOS 使用独立 CI 和发布流程。
- 共享层变更必须验证三个平台。
- Unity 产物通过版本号接入，不跟踪 Unity 仓库分支。
- 客户端发布前检查所声明的契约版本范围、服务端兼容性和 Unity 产物版本。
- Desktop 优先完成完整闭环，Android 和 iOS 按平台能力逐步接入。
- 三端音频参数（采样率、帧长、编码）与视觉参数（分辨率、编码、触发策略与关键帧上行上限）必须一致。
- 模式切换一致性：同一轮回复在任一互动模式下都完整表达，切换不重放回复、不丢动作与音频。
- 通话态上行参数（分辨率、帧率、编码、带宽上限）三端一致；通话中断时降级为所在模式与文本对话，不打断会话。
