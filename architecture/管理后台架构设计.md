# 管理后台架构设计

上位架构：[项目整体架构设计](项目整体架构设计.md)

产品目标：[产品愿景与总纲](../product/产品愿景与总纲.md)

## 1. 仓库定位

`ayane-admin-web` 是面向项目维护者和管理员的独立 Web 前端。

## 2. 功能范围

- 用户和角色管理。
- AI Identity 管理。
- Memory 查看、修正和删除。
- Session 查看和调试。
- 模型供应商配置。
- Prompt 配置。
- 功能开关。
- Agent Runtime 状态。
- 日志、错误和审计查看。

## 3. API 边界

```text
Admin Web
    ↓ 管理员鉴权
Admin API
    ↓
ayane-agent-service
```

管理后台不能使用 Client API 绕过管理员权限，也不能直接访问数据库。

## 4. 权限分层

- 只读管理员：查看用户、Session、Memory 和日志。
- 内容管理员：管理 Identity、Memory 和 Prompt。
- 系统管理员：管理模型配置、功能开关、权限和基础设施状态。
- 所有高权限操作必须进入审计日志。

## 5. 与客户端的区别

| 维度    | 管理后台      | 普通客户端                    |
|-------|-----------|--------------------------|
| 使用者   | 管理员       | 普通用户                     |
| 接口    | Admin API | Client API               |
| 权限    | 高权限、可审计   | 用户级权限                    |
| 发布    | 独立 Web 发布 | Android、Desktop、iOS 独立发布 |

## 7. 技术栈选型

| 层级 | 推荐方案 | 备选 / 说明 |
|------|----------|-------------|
| **框架** | **React 18 + TypeScript** | 生态成熟、类型安全、团队可复用前端经验 |
| **构建工具** | **Vite** | 启动快、HMR 好、配置简单 |
| **路由** | **React Router v6** | 标准选择、支持懒加载、嵌套路由 |
| **状态管理** | **Zustand** + **TanStack Query (React Query)** | 轻量全局状态 + 服务端状态分离、缓存/重试/乐观更新开箱即用 |
| **UI 组件库** | **Ant Design v5** | 企业级后台组件齐全、表格/表单/图表/权限控制完善、TypeScript 支持好 |
| **表单** | **React Hook Form** + **Zod** | 性能好、类型安全验证 |
| **图表/可视化** | **Recharts** 或 **ECharts (echarts-for-react)** | 监控面板、Memory/Session 统计需要 |
| **国际化** | **i18next** | 后台多语言预留 |
| **代码规范** | **ESLint (推荐配置) + Prettier + TypeScript strict** | 统一风格 |
| **测试** | **Vitest** + **React Testing Library** | 单元/集成测试 |
| **Mock / 契约测试** | **MSW (Mock Service Worker)** + **Orval** | 本地开发解耦、从 Contracts 生成类型并做契约测试 |
| **CI/CD** | **GitHub Actions** → Docker → 部署到基础设施 | 与项目其他仓库一致 |

> **备选说明**：若团队强烈偏好 Kotlin 全栈，可考虑 **Kotlin/JS + Compose for Web**，但生态、招聘、组件库成熟度远不如 React，Phase 1 不建议冒险。

## 8. 前端架构分层

```
ayane-admin-web/
├── src/
│   ├── app/                    # 应用入口、Provider、路由配置
│   ├── features/               # 业务功能模块（按领域划分）
│   │   ├── auth/               # 登录、Token 管理、权限指令
│   │   ├── users/              # 用户/角色管理
│   │   ├── identities/         # AI Identity 管理
│   │   ├── memories/           # Memory 查看/修正/删除
│   │   ├── sessions/           # Session 查看/调试
│   │   ├── model-config/       # 模型供应商配置
│   │   ├── prompt-config/      # Prompt 配置
│   │   ├── feature-flags/      # 功能开关
│   │   ├── runtime-status/     # Agent Runtime 状态
│   │   └── audit-logs/         # 日志/审计查看
│   ├── shared/                 # 跨功能复用
│   │   ├── api/                # API 客户端、类型定义（从 ayane-contracts 生成）
│   │   ├── components/         # 通用 UI 组件（表格、表单、弹窗、空状态等）
│   │   ├── hooks/              # 通用 Hook
│   │   ├── utils/              # 工具函数
│   │   ├── constants/          # 常量、枚举
│   │   └── styles/             # 全局样式、主题 Token
│   └── widgets/                # 组合型组件（如：Dashboard 概览卡片、权限受控表格）
├── public/
├── tests/
├── package.json
├── tsconfig.json
├── vite.config.ts
└── dockerfile
```

### 8.1 关键设计点

1. **API 类型共享**：从 `ayane-contracts` 生成 TypeScript 类型（用 `orval` 或 `openapi-typescript`），避免手写 DTO
2. **权限分层**：
   - 路由级：`RequireAuth` + `RequireRole([...])`，取值覆盖第 4 节的三类角色：`read_only_admin`、`content_admin`、`system_admin`
   - 组件级：`<Permission required="identity:write">` 包裹按钮/列
   - API 级：统一拦截器注入 Admin Token，403 统一跳转
3. **审计日志**：所有写操作（POST/PUT/DELETE）在 TanStack Query `onMutate` 中自动记录操作上下文，或由后端强制审计
4. **实时状态**：Agent Runtime 状态、日志尾部用 WebSocket（Admin API 提供 `/ws/runtime`、`/ws/logs`）
5. **主题**：Ant Design ConfigProvider + CSS Variables，支持浅/深色切换
6. **Mock / Contract Testing**：引入 MSW 做本地开发解耦，配合 `ayane-contracts` 生成的 OpenAPI 做契约测试

## 9. 与现有架构的契合点

| 约束 | 实现方式 |
|------|----------|
| 只访问 Admin API，不绕过权限 | 独立 API 客户端 `adminApi.ts`，BaseURL 指向 `/admin`，不复用 Client API |
| 独立部署，不进入客户端仓库 | 独立 repo `ayane-admin-web`，独立 CI/CD，Docker 镜像部署 |
| 权限分层（只读/内容/系统） | RBAC 映射到前端路由/组件/按钮级权限指令 |
| 审计所有高权限操作 | 前端统一埋点 + 后端强制审计双重保障 |
| 协议版本同步 | CI 中校验 `ayane-contracts` 版本与前端生成类型版本一致 |

## 10. 起步建议（Phase 1 最小集）

1. **脚手架**：`npm create vite@latest ayane-admin-web -- --template react-ts`
2. **安装核心依赖**：`react-router-dom @tanstack/react-query zustand antd @ant-design/icons react-hook-form zod i18next`
3. **配置**：ESLint + Prettier + TypeScript strict + Path Aliases (`@/`)
4. **从 Contracts 生成类型**：`orval --input ../../ayane-contracts/openapi/admin.yaml --output src/shared/api`
5. **先跑通**：登录 → Token 存储 → 受保护路由 → 一个列表页（如用户列表） → 分页/搜索/新建/编辑/删除
6. **逐模块迭代**：按功能范围优先级（用户/权限 → Identity → Memory → Session → 配置 → 审计）
