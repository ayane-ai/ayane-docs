# 同步状态与冲突规则

## 状态位置与用途

状态文件位于文档根目录的 .agents/notion-sync/state.json，首次实际同步时才创建；预览不写该文件。
这是同步元数据，不是上游产品文档，不同步到 Notion。不得保存 Token、Cookie、API Key、附件签名 URL 或用户正文。写入使用原子替换，避免部分成功损坏完整映射；已有状态未知版本时停止写入，不重置。

每次执行都完整读取此参考文档。状态至少记录：

| 层级 | 字段及含义 |
| --- | --- |
| 全局 | 状态格式版本、规范化算法版本、目标工作区 ID（可获取时）、目标根页面 ID |
| 文档 | 随机生成且不随路径变化的稳定文档 ID、相对路径、Notion 页面 ID、页面 URL |
| 期望映射 | 页面标题、父文档 ID或目标根页面 ID |
| 已验证基线 | 本地正文 SHA-256、远端规范化正文 SHA-256、远端标题和父级、映射 SHA-256、验证时间 |
| 操作状态 | pending、verified、conflict、missing-local 或 blocked；实际异步任务 ID、已知页面 ID及最近一步 |
| 待完成操作 | 创建前记录的文档 ID、目标父级、目标标题、操作时间及已知结果，用于恢复而非认定成功 |

相对路径统一使用正斜杠，路径比较遵循实际文件系统规则，文件名大小写本身仍保留。
稳定文档 ID 是本地随机标识，不根据标题生成，不修改文档正文以嵌入标记。
改变状态格式或规范化算法版本时需重新核验基线，不能把新算法的结果误判为远端改动。

## 指纹与保真比较

本地正文指纹以 UTF-8 文本为输入，只统一换行到 LF；保留所有正文空格、代码缩进、Mermaid、表格内容与顺序。
标题、期望父级、转换规则版本和已解析的内部链接目标共同纳入映射指纹，避免链接目标或入口标题变更被误当作无变化。

远端指纹基于成功回读的块结构和内容，排除工具返回的抓取时间、编辑时间等非正文元信息。标题、父级单独保存在已验证基线内并参与冲突判断。
代码和 Mermaid 保留语言及字面内容；表格保留单元格、行列和内容顺序；链接比较实际目标；折叠、引用和列表保留语义层级。
不允许只比较字符长度、关键词或代码块数量后声称内容一致。

本地和远端哈希用于各自与各自历史基线比较，不直接比较原始 Markdown 与 Notion 序列化结果的哈希。
跨格式内容保真使用规范化后的语义块序列，并单独逐块比对代码 payload；只忽略可明确归因于表示格式的差异。

同步过程中由本次已确认创建、移动引起的受管理子页面引用变化可纳入预期结果；未管理引用或来源不明的差异不能被忽略。
页标题、父级、子页面引用、正文必须分别核对，不能去掉所有 page 标签后就宣称父页未变。

## 变更判定

| 当前状态 | 动作 |
| --- | --- |
| 本地、远端和期望映射都与基线一致 | 不写入，报告不变 |
| 仅本地正文或期望映射变化，远端仍符合基线 | 精确更新；必要时更新标题或移动已映射页面 |
| 本地与远端已语义一致、标题及父级符合期望 | 不重复写正文，回读核验后可更新基线 |
| 远端正文、标题或父级有独立修改 | 标记冲突，不覆盖远端、不自动回写本地；独立无冲突项可继续 |
| 两边都修改且不一致 | 报告双方差异，等待用户决定，不自动选本地或较新版本 |
| 首次映射到已有页面且内容不同 | 等待用户明确采用本地、保留远端或先合并 |
| 本地新增且没有已映射页面 | 在明确目标根和授权范围内新建 |
| 本地文件消失 | missing-local；保留远端页面与映射，不自动删除或归档 |
| 已映射页面无法访问或疑似已删除 | blocked；不能当作首次新增重新创建 |

首次使用目标根：将根 README 映射到用户指定的根页面本身。若目标根已有不同正文，不能因“指定为根页面”而推断可覆盖正文；先请求用户决定。
查找可复用页面时，标题只能提供候选。核对目标父级、内容及已有映射；多个同名候选不得自动选取。

## 重命名、移动与局部同步

保留同一文档 ID和页面 ID。只有用户明确指定旧新路径、Git 能唯一证明重命名，或一删一增且完整正文指纹唯一对应时，才自动迁移路径映射；内容也变且匹配不可靠时询问，不按相似标题匹配。
重命名文件不强制改页面标题，标题取决于入口映射或文档标题；目录移动按已定义的页面树处理。
远端独立移动视为冲突；只有用户请求覆盖的目录调整才操作远端父级。缺少 move 能力时报告，不能靠创建副本加删除旧页模拟。

局部同步允许读取其他文档来解析链接，但不因此更新它们。已映射的外部范围文档可直接被引用；缺失页面 ID且创建会扩大范围时，先明确需要新增哪些依赖页面。
根、入口或目标页面存在冲突时，依赖其成功处理的页面保持待完成；不依赖的页面可以继续。

## 两阶段写入与中断恢复

1. 创建前持久化 pending 操作意图和已知父级；缺失页面仅建标题，取得 ID 后立即保存映射，正文成功基线保持为空。
2. 已有页面记录旧基线，写入前再次读取检查；工具支持精确匹配或条件写入时使用它。不能声称无条件接口能保证完全消除并发竞争。
3. 页面 ID 可用后补全链接并写正文；验证成功才一次性提交该页新的正文、标题、父级和映射基线。
4. 异步返回 task ID：持久化该 ID，按工具说明查询到终态。超时不代表未创建。
5. 状态未知且无 task ID：检查目标父级的子页面及创建时间、标题等证据；能唯一确认是本次创建才认领。多个候选或无法证明归属时停止该页，不盲目重试。
6. 已创建但正文未完成：下次沿用已保存的 page ID补写。写入已成功而基线未存时，先回读并做语义一致比对，不能直接报告冲突或重新建页。
7. 保存部分成功，失败页面仍为 pending/blocked，保留最后成功基线。最终报告必须体现已创建的未完成页面。
8. 本地文件在执行期间变化时，不用新内容覆盖本次快照；标记需要重新预检，避免把未经验证的内容记成成功。

## 离线演练场景

- 首次清单：根 README → 三个中文入口 → 架构七页与现有调研页；来源链接不会成为自动覆盖目标。
- 再次同步且双方不变：零写入。
- 单篇本地修改：只更新该页，无需重建页面树。
- 远端修改：冲突页跳过，不推进其基线。
- 改名且内容相同、唯一对应：沿用文档和页面 ID；路径与需要调整的链接进入差异清单。
- 删除本地文件：只标记 missing-local。
- 创建请求中断：查任务或唯一的本次创建证据后恢复；不重复创建。
- 未管理子页面、未知块、坏链接、无法转换的锚点或附件：保留内容并报告受影响页，不能默默丢弃。
