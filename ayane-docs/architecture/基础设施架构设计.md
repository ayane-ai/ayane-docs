# 基础设施架构设计

上位架构：[项目整体架构设计](项目整体架构设计.md)

产品目标：[产品愿景与总纲](../product/产品愿景与总纲.md)

## 1. 职责

`ayane-infrastructure` 负责项目运行环境，不承载产品业务逻辑。

- Agent Service 部署。
- Admin Web 部署。
- 数据库和缓存。
- Secret 和环境变量。
- 日志、监控和审计。
- CI/CD 和版本发布。
- 开发、测试、预发布和生产环境。

## 2. 环境划分

```text
开发环境
    ↓
测试环境
    ↓
预发布环境
    ↓
生产环境
```

每个环境拥有独立的数据库、Secret、模型配置和日志范围。生产 Secret 不进入客户端、Git 仓库或文档示例。

## 3. 部署对象

```text
ayane-agent-service
    ├── Client API
    ├── Admin API
    └── WebSocket

ayane-admin-web
    └── Admin UI

Data Services
    ├── Identity / Memory Storage
    ├── Session Storage
    ├── Logs / Audit
    └── Cache
```

Desktop、Android、iOS 和 Unity 产物由各自仓库构建并发布，不由基础设施仓库保存工程源码。

## 4. 安全边界

- 云端 OpenAI-compatible API Key 只注入 Agent Service。
- Admin API 使用独立管理员凭据和权限。
- Client API 使用用户级凭据。
- 日志脱敏，不记录完整 Secret 和敏感记忆内容。
- 生产数据库禁止被客户端直接访问。

## 5. 发布顺序

```text
ayane-contracts
    ↓
ayane-agent-service / ayane-admin-web
    ↓
ayane-unity-embodiment 版本化产物
    ↓
ayane-client
    ↓
Desktop / Android / iOS
```

发布前必须检查契约版本、服务端兼容性、Unity 产物版本和客户端最低版本。

## 6. 可观测性

- Agent 请求耗时。
- 模型调用耗时和错误率。
- Session 连接状态。
- Memory 读写失败。
- Action Event 投递失败。
- Unity Bridge 连接失败。
- Admin 高权限操作审计。
