设计令牌

一个文件、四张视图：令牌取值以两个原型的实测视觉为权威，命名与刻度结构对齐 NomiKit 的九级 （tiny → colossal）。改 src/base/tokens.css 一处，令牌表、组件示例与两张画布同时变。 唯一取值源也是全项目唯一允许出现颜色字面量的文件；下表由 tools/tokens-report.mjs 解析该文件的分组与行内注释生成，「NomiKit 对照」列取自 @nomikit 标注。 宽度断点全部走容器查询（@container region），区域内高度一律取 var(--viewport-h)，因此画布嵌入还是全屏、缩放还是平移，档位表现一致。

组件库

九份组件源，两份原型共用。整页是一张固定宽的大卡片，卡内先按用途分类， 类内一行一组件：左侧编号与说明，右侧把该组件的全部变体横向铺开。 卡片比窗口宽时靠画布平移与缩放看，排版因此不会退回竖排。

客户端原型

登录 → 共用形象页 → 独立媒体开关演示 → 对话记录与账号资料。手机与桌面复用同一套交互；不调用真实设备或后端。 画布是 [data-proto="client"]，宽度断点 767 / 768 / 1199 / 1200 / 1600 与 getLayout() 同源。

交付物：dist/绫音设计规范与交互原型.html（由 node tools/build.mjs 展开 @include 生成， 头部带源码 sha256 指纹）。请勿手改产物；改样式改 src/，改结构改 src/design-system.html。

  • 静态检查：CSS 花括号与注释配平、JS node --check、id 全局唯一、标签配平、 getElementById 与 .id === 目标存在、令牌无悬空、画布禁 CSS zoom —— 全部由 tools/check.mjs 把关。
  • 渲染验证：pwsh .review/run.ps1 -Region both -Mode both，读取版本控制内的回归清单，对两区 × 嵌入/全屏及规范页截图并做断言、几何审计， audit.json 场景准备、状态断言与页面脚本错误必须全部通过。
  • 已验证盲区：headless 下 env(safe-area-inset-*) 恒为 0、无软键盘、无真机 DPR>1， pointer: coarse 只能靠触摸模拟间接推断，这些项只能标为未验证。
